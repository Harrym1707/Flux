## Mission A — reverse-engineer popular GitHub agents' token usage

Goal: read the request-construction code of the most-used open-source agents
and extract, per agent, (1) how they assemble context each turn (full-history
resend? summarisation? truncation?), (2) tool-schema handling (sent every
turn? how many bytes?), (3) any caching they do or break, (4) retry behaviour,
(5) the measurable waste FLUX levers would remove — mapped to EXISTING levers
first, new lever candidates only with a priced mechanism.

Targets (by stars/usage, request-path code only): Cline, OpenHands, Aider,
SWE-agent, gpt-researcher, CrewAI, LangGraph (prebuilt agents), AutoGen,
OpenAI Agents SDK examples, Claude Agent SDK examples.

Rules of evidence: cite file+line in the target repo at a pinned commit. A
waste claim must be derivable from the code (bytes resent per turn × pricing)
or from a wire capture — never "probably". Output: one section per agent in
docs/rnd/knowledge/, plus lever-backlog entries for anything new, each with an
adversarial "why this might be wrong" paragraph.

## Mission B — image and video generation workloads

Founder: these look like massive AI use cases; find where FLUX can honestly
reduce spend. Honesty constraints up front:

- Per-image/per-second generation pricing (DALL-E, gpt-image, Runway, Sora,
  Veo, SD APIs) is NOT token-priced; FLUX text levers do not apply to the
  generation charge itself. Never imply they do.
- The honest levers to investigate: (1) VISION INPUT tokens — images sent INTO
  token-priced models (Claude: ~(w×h)/750 tokens; OpenAI: tile-based) are
  often massively oversized; right-sizing before send is lossless above the
  model's max useful resolution and is end-user-verifiable. Size the win from
  the providers' own published formulas. (2) Duplicate-generation detection —
  byte-identical or near-identical generation requests re-billed; FLUX already
  meters byte-identical retries, extend the mechanism. (3) Retry/failure
  metering on generation endpoints (billed failures are real money). (4)
  Multi-frame video-understanding inputs (frames into vision models) — same
  right-sizing math at per-frame scale.
- Every number traces to a provider pricing page with a checked date, or a
  runnable computation. Estimates labelled. If the verdict is "FLUX cannot
  help this workload honestly", that verdict ships — it becomes a
  do-not-pay-us segment on the site.

Output: docs/rnd/knowledge/2026-10-27-image-video-economics.md + lever-backlog
entries (or an explicit no-lever verdict per workload).
