## 3. Combined `#12` + `#15`: the two proxy-overhead fixes stack, ~40% combined

`#12` (2026-11-01) memoizes `countTokens` within one `reduceRequest` call (de-dupes
~103→~79 repeat calls/request over overlapping slices of the same tools/messages). `#15`
(2026-11-04) rewrites `approximateTokenCount` itself to classify each chunk from one regex
capture-group pass instead of two extra `.test()` passes. Different root causes, different
files (`packages/sdk-js/src/reduce-request.ts` vs `packages/core/src/token-reduction.ts`) —
confirmed by diff inspection before merging, not assumed.

Merged both branches into one (`git merge`, two conflicts: both predate the Mesh rename
and both touch the same `evidence.md` row — resolved keeping Mesh naming and both
write-ups as adjacent rows "(1/2)"/"(2/2)"). Build clean; **539/539 tests** (523 + 16 new
from the two branches). `run-cache-decomposition.ts` unchanged to the decimal (37.9% /
57.3% / 31.3%) — confirms the counter rewrite is behaviour-preserving, not just faster.

`run-proxy-overhead.ts`, this container (linux/x64), 800 req/arm, concurrency 8, 3 runs
each:

| | mean added | p50 added |
|---|---|---|
| `main` (neither fix), 3 runs | 55.00 / 55.67 / 56.05 ms | 53.17 / 52.38 / 54.15 ms |
| both fixes combined, 3 runs | 32.86 / 33.70 / 32.44 ms | 30.24 / 32.65 / 30.53 ms |

**~40% lower added latency combined** — more than either fix alone (#12 measured ~28%,
