## Hardening: `$defs`/`$ref` dangling-reference bug in tool-schema minification

### The bug

`minifyToolSchemas` (`packages/core/src/tool-schema.ts`) is already wired
into the production path (`reduceRequest` in
`packages/sdk-js/src/reduce-request.ts`, levers `tool-schema-compaction` /
`tool-schema-description-trim`) and is on by default (`config.toolSchemas
!== false`). It treated `$defs` as pure plumbing — "schema plumbing the
model never reads" — and dropped the entire container unconditionally,
reporting the removal as a **lossless** saving.

That is false for any tool catalogue built from nested object types, which
is exactly what pydantic `BaseModel`s compile to (CrewAI, AutoGen, and
LangChain tools built on pydantic all serialise this way —
https://docs.pydantic.dev/latest/concepts/json_schema/ — and this matches
last night's own dataset finding that tool-schema weight is universal across
agent corpora, 48-80% of the cold first request). Pydantic v2's
`.model_json_schema()` puts a nested model's definition in `$defs` and
addresses it from elsewhere in the same schema via `"$ref":
"#/$defs/Name"`. Dropping `$defs` while leaving those `$ref` pointers in
place does not make the schema smaller in any meaningful sense — it makes
the schema **wrong**: the model is asked to produce a `customer` argument
typed only as `{"$ref": "#/$defs/Customer"}` with no definition of what a
Customer is anywhere in the request it receives. The request still
serialises as valid JSON, so nothing in the existing test suite (which had
zero `$ref`/`$defs` coverage before tonight) or in any of the project's own
"is this still valid JSON" checks would have caught it. The realistic
failure mode is a tool call with missing or malformed nested-object
arguments on exactly the kind of tool real multi-agent frameworks ship —
silent, not an error the harness would surface, and the opposite of a
"lossless" claim.

This is not hypothetical: confirmed with a direct repro (nested
`Customer`/`Address`/`LineItem` pydantic-style schema) before touching any
code — the old code dropped `$defs` and left three dangling `$ref`
pointers.

### The fix

`packages/core/src/tool-schema.ts`:

1. Removed `$defs` from `PLUMBING_KEYS` (now just `$schema`, `$id`,
   `$comment`, which are genuinely never addressed by `$ref`).
2. Added `DEFINITION_CONTAINER_KEYS` (`$defs` **and** `definitions` — the
   latter is pydantic v1's and OpenAPI-derived generators' name for the same
   mechanism, draft-07's keyword; same dangling-reference risk, so the fix
   covers both, which is the actual "pydantic-aware" half of T1's two-part
   backlog item).
3. `collectReferencedDefinitionNames`: walks a tool's original (unpruned)
   JSON once and collects every name a `$ref` points at (`"#/$defs/Name"` →
   `Name`). This is **reference-string presence, not reachability from the
   schema root** — a definition referenced only from inside another,
   otherwise-unreferenced definition is still counted as referenced and kept.
   Deliberately conservative: it can retain a few bytes of truly dead
   definitions in a rare dead-definition-chain case, but it can never produce
   a dangling reference. Correctness over maximal compression, stated
   directly in the code comment.
4. `prune`'s walker now special-cases `$defs`/`definitions`: each entry is
   kept (and still recursively minified for ordinary plumbing/title/
   formatting wins) if its name is in the referenced set, or reported as a
   `plumbing`/lossless removal if it is genuinely unreferenced anywhere in
   the tool. If every entry is dropped, the container itself is omitted
   rather than emitted empty.
5. Six new tests in `tool-schema.test.ts`: a referenced entry is kept; a
   *transitively*-referenced entry (referenced only from inside another kept
   definition) is kept; a genuinely unreferenced entry is dropped and
   reported lossless; an entirely-unreferenced `$defs` container is dropped
   whole; and the same transitively-referenced case is repeated for the
   legacy `definitions` keyword. 433 → 437 tests.
6. New eval `evals/run-tool-schema-defs-fix.ts`: builds a realistic
   multi-agent-team fixture (1 orchestrator + 3 specialists, 6 rounds, a
   shared pydantic-shaped tool catalogue with a genuinely dead leftover
   definition included on purpose) and prices three arms through the
   simulator at catalogued Sonnet 5.5 rates — raw, the reconstructed OLD
   buggy behaviour, and the FIXED minifier — asserting by construction that
   the old arm produces dangling `$ref`s and the fixed arm does not.

### Measured effect

`node --import tsx evals/run-tool-schema-defs-fix.ts`, multi-agent team (4
agents x 6 rounds = 24 requests), catalogued Sonnet 5.5 prices, caching off
(isolating the minifier's own effect):

| arm | tokens | cost | dangling `$ref`s |
|---|---|---|---|
| A. raw catalogue (no minify) | 29,892 | $0.1126 | — |
| B. OLD buggy minify (`$defs` dropped unconditionally) | 21,972 | $0.0967 | **4** (`Assignee`, `Label`, `ScheduleDeployArgs`, `Hunk`) |
| C. FIXED minify (ref-aware) | 28,884 | $0.1106 | **0** |

B vs A would have shown as a 14.1% "lossless" saving. It was never a
truthful lossless claim — it was silent schema corruption on every
sub-agent's nested-object tool arguments. C vs A is the fix's true
lossless saving on this shape: 1.8% (the catalogue's one genuinely dead
definition, `DeprecatedTarget`, plus the usual plumbing/formatting wins
already covered by the pre-existing tests) — small, honestly reported, and
the correct number.

**Nothing published moves.** Grepped every fixture under `evals/` for
`$ref`/`$defs`: none of `run-agent-ab.ts`'s, `run-cache-decomposition.ts`'s,
or `run-workload-matrix.ts`'s tool catalogues use nested object parameters,
so this bug was latent-but-dormant against every number in `README.md` /
`docs/site/evidence.md` — confirmed by re-running both headline evals above
before touching any source, and `pnpm build && pnpm test` after (437/437,
clean). This is the same category of fix as 2026-10-25's cache-TTL-minimum
guard: the value is in the ledger's `changes` record being truthful on real
customer traffic shaped like this (which the dataset research says is most
multi-agent and autonomous-agent traffic), not in a published number moving.

### Quality gate / replay-gate status

None needed — this is a correctness fix to an existing lossless lever's
definition of "lossless," not a new transform on model-visible content.
The fixed behaviour is *more* conservative than before, never less: it can
only retain bytes the old code dropped, never drop something the old code
kept.
