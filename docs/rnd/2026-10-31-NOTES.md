### 1. A genuine edge case in the shipped lever, found by designing the proxy

`dedupeRepeatedLeadingBlock` (packages/core/src/token-reduction.ts)
dedupes every later turn against **turn 1, forever, with no bound**. On a
long-running memory agent (`evals/run-memory-agent-dedup.ts` runs 40
turns), turn 40's marker points 39 turns back to the only verbatim copy.
This is exactly the attention-distance risk the lever's own doc comment
already named, just never given a concrete mechanism to fail against.

### 2. The fix: bounded re-anchoring

`dedupeRepeatedLeadingBlock` and `crossTurnMemoryDedup` (both files above)
now take `maximumAnchorGap` (turns). Once a turn's gap since the last
*verbatim* occurrence of the memory block would exceed the bound, that
turn is restated in full instead of deduped, becoming the new anchor for
turns after it — so no marker ever points back further than the bound
allows. Left unset, behaviour is byte-identical to before (verified:
`run-memory-agent-dedup.ts` still reports exactly 58.0%, unchanged).
Idempotency holds with the option set too (gap decisions are a pure
function of turn position, not of prior output) — covered by a dedicated
test. 6 new tests: 4 in `token-reduction.test.ts` (unbounded-can-point-
arbitrarily-far control case, bounded re-anchors correctly, idempotency
under the bound, input validation), 2 in `reduce-request.test.ts`
(plumbing through the public config, invalid-value skip-and-report).

### 3. A new grader: `factRecallGrader` (packages/sdk-js/src/graders.ts)

`exactTextGrader` would wrongly punish any wording difference;
`textSimilarityGrader`'s word-overlap F1 would only faintly notice one
missing fact among many shared words. Memory-shaped levers need to ask one
specific question: did the candidate still recall the SAME fact the
baseline did? `factRecallGrader(expectedFact)` reads the expected fact out
of request metadata (fixtures are the only place that genuinely knows
ground truth) and scores 0 only when the baseline recalled it and the
candidate did not — a baseline that itself missed is not a bar the
candidate must clear. 3 new tests in `graders.test.ts`.

### 4. The proxy eval itself: `evals/run-memory-dedup-replay-gate.ts`

Built a stand-in model with one specific, literature-grounded failure
mode: it answers a question about a standing fact correctly only when that
fact's literal text occurs in one of the last `RECALL_HORIZON_TURNS` (4)
user turns of the request it actually received — a simplified, turn-
counted stand-in for the "lost in the middle" long-context literature. 24
turns, 6 rotating facts packed into one memory block, `replayGate` with
`factRecallGrader`, `maximumQualityDrop` left at the library default
(2pp).

**Result:**

```
candidate                                       tokens      cost   quality     bound  verdict
unbounded (shipped: crossTurnMemoryDedup: true)  72.6%     71.6%   -83.3pp   -95.8pp  rejected: breaches 2.00pp limit
bounded (fix: maximumAnchorGap 3)                56.8%     55.8%     0.0pp    -0.0pp  APPROVED
```

The unbounded lever, exactly as shipped, fails this proxy badly: once the
anchor falls outside the stand-in model's recall horizon (turn 5 onward
here), it never recovers for the rest of a 24-turn conversation. The
bounded fix passes cleanly, giving up about 16pp of the candidate's own
saving (72.6% → 56.8%) in exchange for a quality bound of 0.0pp instead of
-95.8pp on this mechanism.

### Honest framing — what this is and is not

This is **not** a live-traffic replay-gate pass and does not promote
`crossTurnMemoryDedup` (bounded or not) to a billable lever. It is a
constructed mechanism, clearly labelled as such in the eval's own output.
What it is: concrete evidence that the risk the lever's docs named for
three nights running is real and triggerable under a plausible model of
long-context recall, and a fix that removes it under that same model
without giving up most of the saving. The real pass — on a customer's own
traffic, real model, real grader — remains open, same as every prior
night; this converts "nobody checked" into "nobody checked with a real
model, but something checked a model of the specific risk already named."

**Deliberately not done tonight:** making `maximumAnchorGap` the default
when `crossTurnMemoryDedup: true` is set. The lever is unbilled and
off-by-default either way, so this is not a published-number question, but
changing a shipped lossy lever's *shape* ahead of the live validation that
would tell us a good bound (too tight wastes saving for no proxy ever
built was asked to confirm; too loose reintroduces tonight's exact finding)
is the same "never bill/ship ahead of its conditions" discipline the lever
already follows for billing. Left as an explicit opt-in option and flagged
below for the founder/next reviewer to decide.
