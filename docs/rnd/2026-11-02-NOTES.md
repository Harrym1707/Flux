## Hardening: model-aware cache minimum threaded into the simulator

### The gap

`anthropicCacheableMinimumTokens(modelId)` (`packages/core/src/
model-prices.ts`) already existed and was already wired into the
production stamping path (`stampAnthropicCacheTtl` in
`packages/sdk-js/src/reduce-request.ts`): 1,024 tokens for Sonnet-/
Opus-class models, 2,048 for Haiku-class, per Anthropic's documented
per-model minimums. But the measurement/eval side never called it.
`packages/core/src/cache-simulator.ts`'s `ANTHROPIC_CACHE_5M` and
`ANTHROPIC_CACHE_1H` policy objects hardcoded `minimumCacheableTokens:
1_024` regardless of model, and `evals/run-workload-matrix.ts` had its own
independent `MIN_CACHEABLE = 1_024` magic number with a comment claiming
it was "the claude-sonnet-5 documented minimum" — true today, but not
tied to the model id the fixture actually sends, so it would silently
stay 1,024 if that fixture were ever pointed at a Haiku-class model. This
was flagged as the queued hardening filler in `2026-10-25-NOTES.md` and
had gone three-plus nights untouched.

### The fix

- Added `anthropicCachePolicyFor(modelId, ttl)` to `cache-simulator.ts`:
  builds the 5m or 1h Anthropic policy from the flat constant, then
  overrides `minimumCacheableTokens` via the existing
  `anthropicCacheableMinimumTokens` helper — one source of truth for the
  minimum, shared by the production stamping path and the simulator.
  `ANTHROPIC_CACHE_5M`/`ANTHROPIC_CACHE_1H` stay exported unchanged (now
  documented explicitly as the Sonnet-/Opus-class default for callers
  with no model id to hand) so no existing import breaks.
- `evals/run-workload-matrix.ts`'s `MIN_CACHEABLE` now reads
  `anthropicCacheableMinimumTokens("claude-sonnet-5-5")` instead of a bare
  `1_024`, and the dead `ANTHROPIC_CACHE_5M` import (unused — this file's
  stamped-path pricing is hand-rolled, not built on `simulateCache`) was
  dropped.
- 4 new tests in `cache-simulator.test.ts`: `anthropicCachePolicyFor`
  returns 1,024 for Sonnet/Opus, 2,048 for Haiku, otherwise matches the
  flat constant it's built from, and — the regression the fix actually
  prevents — a ~1,400-token shared prefix (between the two minimums)
  caches under the Sonnet-class policy but correctly misses
  (`missReason: "below-minimum"`) under the Haiku-class one. Under the
  old flat constant, this case would have wrongly cached for a
  Haiku-class model.
