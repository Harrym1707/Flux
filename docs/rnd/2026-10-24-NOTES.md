## New-lever research: RAG pipeline, duplicate-excerpt dedupe

This picks up **Finding 2** from
`docs/rnd/2026-10-22-workload-matrix-findings.md`, left there in priority
order for exactly this purpose.

### Hypothesis

`evals/run-workload-matrix.ts`'s RAG fixture (`ragPipeline()`) builds each
user turn as:

```
Context:\n${picks.join("\n")}\nQuestion ${index}: ...
```

where `picks` deliberately repeats `EXCERPTS[0]` twice per request (a
realistic RAG behavior: the same passage matches more than one retrieval
query). `dedupeRepeatedBlocks` only ever split on `\n{2,}` (blank-line-
separated paragraphs), so a single-newline join between `picks` never
produced two *top-level* blocks with identical text — the whole joined
block is unique per request because the question text differs. The lever
(`duplicateContext`, already on by default) was computing nothing on this
shape: the matrix run showed `rag pipeline ... cost -0.0% ... WARNING: no
net saving`.

### What was built

`dedupeRepeatedBlocks` in `packages/core/src/token-reduction.ts` now checks
for duplicates at a second granularity, nested inside the existing one: for
any blank-line-separated block that is *not itself* a whole-block duplicate,
split it further on single newlines (safe — by construction there are no
`\n{2,}` runs left inside it, so every newline found is a lone line break)
and drop any line that exactly matches one already kept, using the same
shared `seen` set so a duplicate is caught regardless of which granularity
it first appeared at. Same safety rules as before, extended to the new
granularity:

- Byte-exact match only (a line differing only in whitespace is a different
  line — code and YAML make whitespace meaningful).
- Any block containing a code fence (`` ``` ``) is skipped entirely, at both
  levels — never decomposed into lines, so a legitimate repeated line inside
  a code fixture is never touched.
- The same `minimumBlockTokens` floor (24 by default) applies to lines too,
  so ordinary short repeated phrases ("please answer") are left alone.

No existing call site changed: this is the same `duplicateContext` config
flag (`packages/sdk-js/src/reduce-request.ts`), same `lever:
"duplicate-context-removal"`, same `lossless: true`. It just catches more of
what that lever was already supposed to catch. Version bumped `"1"` → `"2"`
on the reducer id as a provenance marker for this behavior change.

Added to `packages/core/src/token-reduction.test.ts`:
- drops a duplicate excerpt joined by a single newline (the RAG case)
- still catches a duplicate line against an earlier *whole block* (cross-
  granularity, same `seen` set)
- never dedupes a repeated line inside a fenced code block
- never dedupes lines differing only in whitespace
- leaves short duplicate lines alone (parity with the existing short-block test)

### Quality gate / replay-gate status

None needed. This lever removes zero model-visible information (the
dropped line is byte-identical to one the model already has, in the same
message); it stays in the "lossless" bucket by construction, same as the
pre-existing whole-block case. No replay gate required, unlike Finding 1.
