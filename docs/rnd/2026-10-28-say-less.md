# R&D — 2026-10-28: "say less" (FLUX answers to Caveman)

Branch `rnd/2026-10-28-say-less`. Caveman (YC F26, viral open-source plugin)
wins attention with three things: a terse output voice, a memory-file
compressor, and a shareable savings number. This run builds a FLUX version of
each, under FLUX's rules: lossy levers are off by default and bill only behind
the replay gate, and nothing is shared that the ledger cannot prove.

No live API key was available, so **no FLUX number in this note is a live
measurement**. Output reductions are literature-claims with sources;
break-evens and per-shape savings are estimates on those claims. Nothing in
`docs/NUMBERS.md` changes.

## 1. Output concision modes — `outputStyle` lever

`tokenReduction.outputStyle: "off" | "concise" | "terse" | "ultra"` (default
`"off"`; proxy runner: `FLUX_OUTPUT_STYLE`). Code: `packages/sdk-js/src/output-style.ts`,
wired into `reduceRequest` after every text pass and **before** the cache stamp.

Instructions (exact bytes, pure function of the mode):

| mode | text | tokens added (FLUX counter, overcounts ≤1.28x) |
|---|---|---|
| concise | `Be concise.` + carve-outs | 40 |
| terse | `Be terse: no preamble or recap; fragments OK.` + carve-outs | 51 |
| ultra | `Fewest words possible: fragments, no preamble or recap.` + carve-outs | 53 |

Carve-outs (one sentence, every mode): *Keep code, commands, file paths, error
messages and data exact; full sentences for security warnings and irreversible
actions.* Kept short on purpose: Caveman's own table shows "Answer concisely."
gets 6,983 → 4,334 output tokens, against 4,119 for their full rules, which
cost ~1,160 input tokens per turn.

Placement (tested for byte-stability across turns, with and without the cache stamp):

- **Anthropic** string `system`: appended at the end, but *before* any
  per-request tail that `repairCachePrefix` moved there, so the stamped stable
  block covers the instruction and never the clock. Block-array `system`: one
  new text block appended after the caller's last block, so a caller-placed
  breakpoint stays on the block it was on, over the same bytes (FLUX's stamp
  still defers to caller caching). No system prompt: the instruction becomes it.
- **OpenAI Chat**: appended to the last message of the leading system/developer
  run, or a new leading system message. **Responses**: appended to
  `instructions` (before a repaired volatile tail).
- Idempotent (never inserted twice). Turning it on rewrites an existing cached
  prefix once, then it is byte-stable.
- **Skipped** (recorded in `summary.notes`, request untouched) on forced
  `tool_choice` (Anthropic `tool`/`any`, OpenAI `required`/named function/
  `allowed_tools` required) and structured output (`response_format`,
  `text.format`, `output_format`, `output_config.format`).

Billing: recorded as lever `output-style-<mode>`, `lossless: false`,
`estimatedTokensSaved: 0`. Its saving is OUTPUT tokens, which only a replay
measures, so it never bills from the estimated baseline; with a measured
counterfactual it bills only with an approved replay-gate verdict (tested).
The change also carries `estimatedTokensAdded`; the ledger now subtracts added
tokens from provider input before estimating any *other* lever's baseline
(recorded as `estimatedReduction.estimatedInputTokensAdded`), so the
instruction can never inflate a removed-token saving. Existing spools are
byte-unchanged (the field is only written when non-zero).

### Eval — `pnpm eval:output-style` (evals/run-output-style.ts)

Break-even output length O* = I × inputRate / (r × outputRate), Sonnet 5.5 at
catalogued prices. Copied from the run's output; **every row is an estimate on
a literature-claim reduction**:

| mode | instr. tokens | output reduction (literature-claim) | O* uncached | O* cache write (turn 1) | O* cached read (turn 2+) |
|---|---|---|---|---|---|
| concise | 40 | 8.5% agentic (JetBrains) | 94 | 118 | 4.7 |
| concise | 40 | 37.9% chat (Caveman 'Answer concisely.') | 21 | 26 | 1.1 |
| terse | 51 | 8.5% agentic (JetBrains) | 120 | 150 | 6.0 |
| terse | 51 | 41.0% chat (Caveman /caveman) | 25 | 31 | 1.2 |
| ultra | 53 | 8.5% agentic (JetBrains) | 125 | 156 | 6.2 |
| ultra | 53 | 61.4% chat (Caveman /ultracave) | 17 | 22 | 0.9 |
| Caveman full rules | 1,160 | 8.5% agentic (JetBrains) | 2,729 | 3,412 | 136.5 |
| Caveman full rules | 1,160 | 41.0% chat (Caveman /caveman) | 566 | 707 | 28.3 |

The eval also prints break-even on every catalogued model and the estimated
net per FLUX live-export workload shape (mean output 102–743 tokens, n=30).
Findings (estimates):

- With the cache stamp on, the instruction breaks even at ~1–6 output tokens:
  its cost is noise. Uncached, under the conservative 8.5% agentic claim, the
  only losing cases are `already-lean` with `terse`/`ultra` (mean output 102 <
  O* 120–125). `concise` is the cheapest per token saved and the right default
  when turning it on.
- Caveman's full rule set needs ~2,700-token responses to break even uncached on
  agentic work. FLUX's short instruction is the right engineering call.
- The real uncertainty is the reduction itself: 8.5% on agentic coding (a
  forced-on ceiling) vs 38–61% on chat Q&A. Only a live paired A/B settles it:

```
ANTHROPIC_API_KEY=sk-ant-... FLUX_LIVE_MODEL=claude-sonnet-5-5-20260514 node --import tsx evals/run-output-style.ts --live
```

(10 dev questions × baseline + 3 modes through `replayGate`, a same-model
judge for quality; it prints the call count. n=10 is a smoke A/B.)

## 2. `flux compress <file>`

`packages/cli/src/compress.ts`. Deterministic and idempotent compression of
stable memory/instruction files. Removes filler words and wordy phrasing
("in order to" → "to", "It is important that you X" → "X", "please",
"basically", "very"/"really" except after "not"), collapses in-line whitespace
(leading indentation kept) and blank-line runs, and keeps the first copy of a
rule repeated verbatim. Fenced code, inline code, URLs, paths, flags, tables,
shell-prompt lines and numbers stay byte-for-byte. It skips rewrites that would
change meaning ("make sure the build is green" stays; "actually", "clearly" stay).
Writes `<file>.flux-backup` (refuses to overwrite one without `--force`),
prints before/after tokens, edit counts and a unified diff, supports
`--dry-run`, and says LOSSY in every run. On this repo's own docs it finds
almost nothing (README: −2 tokens), as it should on tight files.

## 3. `flux stats` (+ `--share`)

`packages/cli/src/stats.ts`. Reads `./flux-ledger/*.jsonl` (the proxy's spool
dir) or `--ledger <file|dir>` (repeatable), verifies every hash chain, and
reports `recomputeInvoice`'s own numbers: saved (measured vs
estimated-baseline, labelled), spend, requests, cache-read tokens on
FLUX-placed caches, estimated tokens removed, top levers, and unbilled levers.
`--days n` / `--week` window it. `--share` prints one line from **measured
savings only**, rounded down, and refuses on a broken chain or when only
estimates exist. Tested against a committed fixture spool
(`packages/cli/src/__fixtures__/stats-spool.jsonl`, synthetic).

On the 2026-10-26 live export: net $0.0365 saved, of which **$0.0031 is
measured** (cache-ttl-5m) and $0.0333 is estimated-baseline. So the honest
share line is `FLUX saved me $0.0031 (1.5%) on 30 requests so far`.

**Flag for the founder (not edited):** `flux stats` states savings as a share
of what the requests *would have cost* (saved / (spent + saved)) = 15.3% on
that export. NUMBERS.md's 18.2% is saved / spent ($0.0365 / $0.2010). Both use
the same dollars; the denominators differ. Also, ~91% of that 18.2% is
estimated-baseline, not measured. Worth a decision on which framing NUMBERS.md
quotes.
