**Title:** Show HN: FLUX – stop paying twice for the same tokens (local LLM proxy, Claude Code plugin)

**URL:** https://github.com/Harrym1707/Flux

---

Most agents never switch on Anthropic's prompt cache, so every turn re-sends the whole conversation
at full input price. You pay for turn 1's tokens on turn 2, again on turn 3, and so on. FLUX is a
local proxy that sits on one URL between your app and the API and fixes that kind of waste before
the request bills.

Try it:

    npx -y -p @flux-ai/sdk flux-proxy            # then set base_url to http://127.0.0.1:8787

    # or, in Claude Code:
    claude plugin marketplace add Harrym1707/Flux && claude plugin install flux@flux
    /flux        # starts the proxy, points ANTHROPIC_BASE_URL at it
    /flux-stats  # what it saved, from your local ledger
    /flux-off    # back to direct

What it does to the request: stamps a cache breakpoint on the stable prefix (and refuses to when the
prefix churns, because a breakpoint that's never read back only buys write premiums), moves
per-request clocks out of the cacheable prefix, compacts tool schemas losslessly, removes exact
duplicates, and can send latency-tolerant OpenAI traffic to the flex tier. Defaults are lossless.
Responses, SSE included, come back byte-identical.

Numbers, with their labels (all in docs/NUMBERS.md):

- **18.2%** net on our latest live export: 30 real requests, claude-sonnet-5-5, real money. The coding
  agent in that basket saved **38.1%**. Two agents saved 0%, correctly.
- **Up to 72.8%** on one-shot templated traffic that can wait. That's simulator, not live.
- **0–5%** on stacks that are already optimised. The quote tool then tells you not to pay us.

The business model is the part I'd most like criticised. FLUX charges 1% of *verified* savings and
nothing else. Every request writes one hash-chained event with the provider's own usage numbers. The
invoice is a pure function of that ledger, which lives on your machine, and you can run
`recomputeInvoice` on it and must get our number. If a lever loses money (we caught one doing exactly
that on live traffic), the loss counts against us. Prompts never leave your machine except to your
provider. The proxy has no telemetry.

Relationship to Caveman: Caveman makes your agent say less. FLUX makes each request cost less. They
work on different layers. Use both.

Caveats, up front: the bands other than the live ones are simulator-measured. Claude Code already
places its own cache breakpoints and FLUX defers to them, so in Claude Code expect the lossless levers,
not the cache number. Busy interactive agents top out around 29% before cache enablement. Licence is
BUSL-1.1: free to read, evaluate and use non-commercially.

Happy to answer anything about the ledger, the cache-economics simulator, or why "per completed task"
and not "per request" is the only honest unit.
